## 0. 전체 흐름

```
A. 셋업 (반나절)          : 저장소 / 문서 / 외부 의존 점검 / 클로드 코드 헤드리스 응답 형식 확인
       ↓
B. PC 백엔드 인프라 (1~2일) : 도커 컴포즈 / 디비 스키마 / 인증 / 업로드 / 워커들 / 클라우드플레어 터널
       ↓
C. 안드로이드 앱 (3~5일)    : 로그인 / 알림 캡처 / 통화 캡처 / 동기화 / 메인 화면
       ↓
D. 본인 1주일 검증 (1주)    : 본인 폰 + 와이프 폰 둘 다 설치. 일별 메모. 부족 신호 데이터로 정리
       ↓
E. 라이프싱크 + v0.1 폐기  : 단계적으로 알림 권한 회수 / 통화 캡처 끄기 / 노션 박제
```

병렬화 가능 — 단계 B 와 단계 C 는 인증 API (응용 프로그래밍 인터페이스) 의 요청·응답 형식만 먼저 박히면 동시 진행 가능.

## 부록 A — 각 단계의 진짜 검증 질문

- 단계 A: 외부 의존 다 점검됐는지 가정 없이 확인했는가?
- 단계 B: 디비 / 인증 / 워커가 더미 데이터로 끝까지 흐르는가?
- 단계 C: 본인 폰에서 끝까지 흐르는가?
- 단계 D: 1주일 후 지속 사용 의지가 첫날보다 강한가 약한가?
- 단계 E: 부족 신호 데이터가 모였나, 아니면 "그냥 좋겠지" 라는 가정인가?

각 질문에 "음... 잘 모르겠다" 면 다음 단계 가지 말고 멈추기.

## 부록 C — 비상 멈춤 시나리오

- 폰 발열 / 배터리 하루 못 감 → 폰 안 Gemma 추론 가드 튜닝
- 클로드 코드 사용량 폭증 → 일별 처리 카운터 어드민 웹 한 구석에 표시 (단계 E 의존)
- 캡처된 민감 정보 (비밀번호·금융) 가 잘못 할 일로 추출 → 필터 룰 강화
- 법적 회색지대 통화 잡힘 → 발신자 번호 블랙리스트 자동 스킵
- PC 다운 (전원·네트워크) → 폰 로컬 큐에 쌓임. PC 복구 시 재시도. 안 됨 → 단계 D 메모

## 부록 D — 운영 가드 (단계 B / C 구현 시 같이 박을 것)

- 클로드 코드 응답 구조 가정 → 단계 A.2 에서 사전 확인
- 폰 → PC 업로드 실패 → 안드로이드 작업 스케줄러 (`Constraints.NetworkType.CONNECTED`) + 재시도
- 호스트 에이전트 워커 ↔ 도커 디비 연결 끊김 → 자동 재연결
- 토큰 회전 → 디바이스 폐기 명령 (`scripts/revoke-device.sh`) 운영자 알리기
- 비용 모니터링 → 일별 처리 통화 분 수 표시 (어드민 웹 시점에서)
- 노션 박제 전 데이터 내보내기 → 단계 E.1 첫 항목으로 박제 전
