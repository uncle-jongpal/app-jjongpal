# 00 · 정체성·원칙

## 한 줄

> 내 폰의 알림과 통화를 자동으로 잡아서 내가 잊지 않게 해주는 본인용 능동 비서. 단순한 데이터 축적이 아니라 매일의 할 일·약속을 자동으로 추적·정리해서 보여주는 도구.

## 페르소나

- 본인 (어드민이자 일반 사용자) — 자기 데이터 + 어드민 권한으로 다른 사용자 데이터 (웹에서) 본다
- 다른 가족 (일반 사용자) — 자기 데이터만 폰에서 본다

상품화 X. 일반 사용자 대상 앱 X. 본인 가족 단위 사용.

## 7대 원칙

1. **로컬 우선 (local-first)** — 폰의 로컬 디비가 진실의 원천. PC 와의 동기화가 끊겨도 폰은 정상 동작. PC 의 데이터는 합본·깊은 처리용 미러.
2. **프라이버시는 데이터 모델 단에서 강제 (privacy as architecture)** — 외부 LLM API (Gemini / OpenAI) 호출 0. 통화 음성은 텍스트 변환 후 즉시 삭제. 푸시 페이로드에 본문 박지 않음. 사용자 자기 데이터만 봄.
3. **단계적 권한 (progressive permission)** — 한 번에 모든 권한 요청 X. 사용자가 기능을 쓰는 순간에 그 권한만 요청.
4. **되돌릴 수 있게 / 회계 가능하게 (reversible / auditable)** — PC 처리 결과는 transcript 와 함께 보존. 재처리 가능. 처리 이력 로그 종류별 분리.
5. **압축된 컨텍스트 (compressed context)** — 통화 transcript → 정리된 JSON 으로 압축. 본문 그대로 안 들고 다님.
6. **방해 없이 (ambient)** — 통화 끝나면 사용자가 아무것도 안 해도 정리됨. PC 가 알아서.
7. **혼합 (hybrid over dogma)** — 짧고 즉시한 일은 폰 안 로컬 LLM (Gemma 4 E2B + MediaPipe). 깊은 처리는 PC 의 whisper.cpp + Claude Code. 자기 인프라 최대 활용. 외부 의존 0.

## 흔들릴 때 보는 질문

새 기능·새 결정 앞에서 본인이 답해야 하는 것:

1. 이 기능이 할 일의 자동 캡처 / 유지 / 완료 중 어디에 기여하는가?
2. 본인 (또는 와이프) 이 매일 쓸 것인가?
3. 의사결정 위임 스펙트럼에서 더 자동화 쪽으로 한 칸 옮기는가?
4. 외부 의존성이 정말 필요한가, 자기 인프라 (PC, Claude Code, 클라우드플레어 터널) 안에서 가능한가?
5. 검증된 가정 위에 있는가? 안 써본 시스템 위에 그 다음 시스템 설계하면 거의 항상 틀린다.

세 개 이상 답이 약하면 그 기능 / 결정 보류.

## 정체성 잃지 말 것

- 상품화 / 일반 사용자 대상 앱 아님. 본인 + 가족.
- 데이터 축적이 목적 아님. 매일의 할 일·약속 추적이 목적.
- 외부 의존을 늘리는 모든 결정은 다시 검토.
