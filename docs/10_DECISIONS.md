# 10 · 결정 로그

> 작성: 2026-05-20
> 독자: 본인 + 다른 에이전트 (Claude Code 등)
> 형식: 왜 그렇게 결정했는지의 기록. 무엇을 언제는 [20_PHASES.md](20_PHASES.md) 참조.

## 0. 한 줄 요약

> 쫑팔이삼촌 앱은 폰 안 로컬 처리 (Gemma) + PC 깊은 처리 (whisper + Claude Code) 의 혼합. 사용자별 자기 데이터만 폰에서 봄. 어드민 1명만 웹에서 전체 봄. 외부 LLM API (Gemini / OpenAI) 호출 0. 로그인 인증. 식별자 / 모델은 일반 관계형 설계, 의미 단어 하드코딩 X.

## 1. 컨텍스트 — 외부 독자용

이 프로젝트는 한국인 개인 개발자의 개인용 (상품화 X) AI 비서 안드로이드 앱. 본인 + 가족 단위 사용. 일반 사용자 대상 제품 아님.

이전 프로젝트:
- **라이프싱크 (LifeSync, com.lifesync)** — 1년간 운영된 작동 시스템. 알림·SMS·통화 → n8n → 노션 (Notion). 단계적 폐기 대상.
- **assistant (v0.1, app.jongpal.assistant)** — Greenfield 재설계 PoC. M3 까지 구현. 폰 안 Gemma 추론 검증. v0.2 출발점으로 사용 후 동결.

이 저장소 (v0.2, app.jongpal.jjongpal) 는 위 두 프로젝트의 흡수·재구성·확장.

## 2. 결정 1 — 라이프싱크 흡수 후 단계적 폐기

라이프싱크의 유일하게 살릴 가치 있는 자산 (통화 녹음 감지 모듈 — 제조사별 통화 녹음 경로 7개 + 파일 감지 패턴) 만 v0.2 로 이식. 나머지 라이프싱크 인프라 (n8n / 파이썬 파일서버 / 노션) 는 v0.2 검증 후 단계적으로 끔. 노션 1년 데이터는 사전에 JSON·CSV 로 내보낸 후 박제.

### 선택지 비교

- 병합 (merge) → 라이프싱크 부채 (평문 환경설정 저장, 미사용 재시도 카운터, 테스트 0건, n8n 의존) 가 v0.2 에 따라옴. 안 가져가기로 한 것들이 다시 살아남.
- 현상 유지 → 두 앱이 같은 알림 캡처. 운영 부담 지속. 안전망 있으면 진짜 검증 안 일어남.
- ✅ **흡수 후 폐기** → 살릴 것만 이식. 나머지는 단계적 종료.

## 3. 결정 2 — 합본 모델 단순화: 사용자별 격리 + 어드민 1명 웹 합본

- 각 사용자는 폰에서 자기 데이터만 본다.
- 어드민 역할의 사용자는 웹에서 전체 사용자 데이터를 본다.
- 사용자 간 *공유* 모델 (event_shares, share visibility) 만들지 않는다. 공유가 필요해지면 그때 추가.
- 가시성 (visibility) 필드 단순. 별도 공유 테이블 X.

### 결정 이력

이전 안 (v0.1 의 13 문서) 은 단방향 합본 (본인이 와이프 데이터 봄, 반대 X) + private / shared 가시성 두 값이었음. 사용자 의견: "사용자별로 자기꺼만 모바일에서 보고 웹에서 관리자로 볼 수 있으면 되는데 왜 공유가 필요해". → 공유 모델 폐기.

## 4. 결정 3 — 통화 텍스트 변환: 폰이 아닌 PC 에서 whisper.cpp 로컬 실행

폰은 통화 녹음 파일을 PC 로 단순 업로드만. 텍스트 변환은 PC 의 whisper.cpp 가 처리. 외부 API (Gemini / OpenAI Whisper) 의존 0.

폰 측은 발열·정확도 양쪽 다 양보. PC 는 24/7 가동 중이고 본인의 자기 자원.

### 모델 선택

whisper-large-v3 사용. 작은 모델 (tiny / base / small / medium) 은 한국어 통화 (배경잡음 + 두 화자 + 빠른 말) 에서 정확도 처참. large-v3 만 실용적.

화자 분리 (diarization) 는 v1 에서 안 함. 단일 텍스트 스트림으로 받고 Claude Code 에이전트가 컨텍스트로 화자 추론.

## 5. 결정 4 — 통화 정리: PC 의 Claude Code 헤드리스 에이전트

whisper 가 뽑은 transcript 를 Claude Code 헤드리스 호출로 정리. 출력은 JSON: `{summary, todos[], appointments[], people[], action_items[]}`. 결과는 디비에 저장 + 파이어베이스 클라우드 푸시 (FCM, 구글 모바일 푸시 서비스) 트리거로 폰에 알림.

근거: 본인이 Anthropic Pro/Max 구독자라 Claude Code 사용량은 한계비용 0 (정액제). 외부 API 호출 = 추가 과금이지만 Claude Code = 이미 지불한 비용 안.

품질도 통화 정리 / 추출 작업에서 Claude Sonnet / Opus 가 다른 외부 LLM 대비 좋음.

### 폰 안 Gemma 와의 역할 분담

- 알림 (짧은 텍스트, 즉시) → **폰**: Gemma 4 E2B (MediaPipe LLM, 구글 온디바이스 추론 도구)
- 통화 (긴 텍스트, 지연 OK) → **PC**: whisper + Claude Code

## 6. 결정 5 — 폰 우선, 웹은 어드민 전용

- 일반 사용자: 폰 안 자기 화면 + 자기 데이터 + 알림 / 통화 정리 결과.
- 어드민: 폰 + 웹. 웹에서 전체 사용자 데이터 합본 뷰.

웹 UI 의 일반 사용자용 화면 (회고·검색·트렌드 분석) 은 v1 에서 안 함. 부족하다는 데이터가 모이면 그때 결정.

## 7. 결정 6 — PC 인프라: 도커 컴포즈 한 묶음

본인 PC 에 도커 컴포즈 한 파일로 다음 묶음 운영:

- Postgres (포스트그레큐엘 17, 관계형 디비) — 데이터 저장
- PostgREST (자동 REST 입구) — 폰 ↔ PC REST API
- 인증 서비스 (FastAPI) — 로그인·재발급·로그아웃
- 업로드 수신기 (FastAPI) — 통화 파일 받음, 디비 등록
- whisper 워커 (도커) — STT 후 통화 음성 파일 즉시 삭제
- 에이전트 워커 (호스트 systemd) — Claude Code 헤드리스 호출 (도커 안에서 못 해서 호스트에 둠)
- 파이어베이스 푸셔 (도커) — 디비 변경 감지 → 폰 푸시
- 엔진엑스 (nginx) — 인증·업로드·REST 라우팅
- 클라우드플레어 터널 (Cloudflare Tunnel, 외부 보안 통신로) — 영구 셋업

자세한 컴포즈 / 스키마 / 워커 코드 [30_PC_PIPELINE.md](30_PC_PIPELINE.md) 참조.

## 8. 결정 7 — 로그인 인증 (이메일 + 비밀번호)

이전 안 (v0.1) 은 빌드 변종 (variant) 으로 사용자 ID + 토큰을 빌드 시점에 박았음. v0.2 는 로그인 흐름으로 전환.

근거:
- APK (안드로이드 설치 파일) 한 개로 OK. 폰 교체 시 새 빌드 불필요.
- 토큰 회전 (디바이스 폐기·비밀번호 재설정) 이 자연스러움.
- 새 사용자 (자식·친척 등) 추가가 단순.
- 빌드 시점 토큰 박기의 보안 약점 (APK 추출 시 토큰 노출) 회피.

### 인증 API 3개

- `POST /auth/login {email, password}` → access_token + refresh_token
- `POST /auth/refresh {refresh_token}` → 새 access_token
- `POST /auth/logout {refresh_token}` → refresh_token 폐기

### 토큰 정책

- access_token 만료: 1시간
- refresh_token 만료: 90일
- refresh_token 은 디바이스 단위. 폰 분실 시 어드민이 운영 스크립트로 즉시 폐기 가능 (`scripts/revoke-device.sh`).
- 폰 측 토큰 저장: 안드로이드의 EncryptedSharedPreferences (안드로이드 기본 암호화 키-값 저장소). 평문 X.

### 비밀번호 보관

- 디비: bcrypt 해시 (안전한 비밀번호 해시 알고리즘) 만 저장. 평문 X.
- 운영 스크립트 `scripts/create-user.sh <email> <name> <role>` 으로 어드민이 사용자 생성. 초기 비밀번호 발급 후 사용자가 첫 로그인 시 변경 권장.

## 9. 결정 8 — 사용자 ID 일반화

사용자 식별자 (`users.id`) 는 일반 ID (자동 증가 정수 또는 UUID, 보편 고유 식별자). 의미 단어 (`me`, `wife`, `admin` 같은 값) 어디에도 박지 않는다.

역할은 `users.role` 컬럼 ('admin' / 'user') 으로 별도 표현. 본인은 role='admin' + 일반 사용자 데이터도 같이 가짐.

푸시 라우팅·데이터 매핑·코드의 분기 어디서도 사용자 ID 의 *값* 을 비교하지 않는다. 비교는 *역할* 또는 *데이터 관계* 로만.

## 10. 결정 9 — 푸시 라우팅 단순

푸시 대상 결정:
- 어떤 이벤트 / 요약이 새로 생기면 그 데이터의 사용자 ID 를 본다.
- 그 사용자 ID 에 속한 활성 디바이스 (`devices` 테이블에서 `user_id = <user_id> AND revoked_at IS NULL`) 모두에 푸시.
- 교차 라우팅 / 공유 라우팅 X.

## 11. 결정 10 — 파이어베이스 푸시: 본문 없는 데이터 전용

푸시 페이로드는 `{"type": "summary_ready", "summary_id": "..."}` 같은 트리거만 박는다. 실제 본문은 폰이 PC 의 REST API 에서 다시 가져온다.

근거: 구글 인프라가 푸시 메타데이터 (누가 / 언제 받았다) 는 보더라도 통화 요약 / 본문은 못 보게. 프라이버시 원칙 (00_VISION §2) 의 데이터 모델 단 강제.

자체 호스팅 푸시 (ntfy.sh, 유니파이드푸시 등) 는 안드로이드 도즈 (Doze, 전력 절약 모드) 에서 신뢰성이 떨어져 v1 에서 안 씀. v2 에 자체 호스팅 푸시 추가 또는 교체 검토.

## 12. 결정 11 — 통화 음성 파일은 텍스트 변환 직후 즉시 삭제

전체 통화 .m4a 파일은 영구 보관하지 않는다. whisper 워커가 텍스트 변환 끝내자마자 파일 삭제. 디스크에는 transcript (텍스트) 만 영구 보관.

근거:
- 디스크 용량 최소화
- 음성 자체의 민감 데이터 (목소리 / 배경음) 가 디스크에 남지 않음
- 텍스트만으로 회고 / 검색 가능

## 13. 결정 12 — 프롬프트 버전 추적

PC 의 Claude Code 호출에 사용한 프롬프트의 버전 (해시 또는 버전 문자열) 을 `summaries` 테이블에 같이 저장. 프롬프트 개선 시 어떤 transcript 가 어떤 버전으로 처리됐는지 회고 가능.

`pc/agent-worker/prompts/` 안의 프롬프트 파일이 변경되면 자동으로 새 버전 해시. 워커 시작 시 해시 계산해 메모리에 들고 있음.

## 14. 결정 13 — 처리 이력 로그 종류별 분리

처리 이력 (언제 어떤 일이 어떻게 됐는지) 을 한 테이블에 모으면 종류별 식별자 형식 충돌이 남. 종류별로 별도 테이블 (`audio_processing_log`, `transcript_processing_log` 등) 로 분리.

각 테이블 안에서는 그 종류의 외래키만 사용. 미래에 새 종류 (예: 알림 처리 로그) 추가 시 새 테이블 만들기.

## 15. 결정 14 — 한 폰 = 한 사용자

`devices` 테이블의 `user_id` 필수. 한 폰을 두 사용자가 공유하는 시나리오 안 받음.

## 16. 결정 15 — 사용자 시각의 진실은 서버 시각

이벤트 발생 시각 (`events.timestamp`) 은 PC 가 받은 시점 기준. 폰 시계는 어긋날 수 있어 신뢰하지 않음.

폰 측에서 보내는 시각 (`device_timestamp`) 은 보조 메타 (지연 측정·디버깅) 로만 별도 컬럼에 보관.

## 17. 의도적으로 보류 / 거절한 것

- ❌ 폰 안 STT (whisper-tiny 등) — 발열 / 정확도
- ❌ 외부 LLM API (Gemini / OpenAI 등) — 비용 + 프라이버시
- ❌ 화자 분리 — 셋업 복잡, Claude 가 추론
- ❌ 별도 일반 사용자 웹 UI — 부족 신호 모이면 결정
- ❌ 사용자 간 공유 모델 — 어드민 + 일반 사용자 격리로 충분
- ❌ 노션 데이터 마이그레이션 — JSON·CSV 로 내보내고 박제
- ❌ 자동 위임 / 자동 액션 실행 — 미래

## 18. 외부 에이전트 핸드오프 핵심 사실

다른 에이전트 (Claude Code 등) 가 이 시스템 코드 작성·수정 시 알아야 할 것:

1. 사용자 식별자는 일반 ID. 'me' / 'wife' / 'admin' 같은 의미 단어 어디에도 박지 않는다.
2. 사용자는 자기 데이터만 본다. 공유 모델 없다.
3. 어드민 (role='admin') 만 다른 사용자 데이터를 본다. 웹에서만.
4. 한 폰 = 한 사용자. devices.user_id 필수.
5. 외부 LLM API 호출 X.
6. 폰에서 직접 Anthropic API 호출 X. 폰은 PC 와만 통신.
7. 사용자 시각의 진실은 서버 시각.
8. 통화 음성 파일은 텍스트 변환 직후 즉시 삭제.
9. 푸시 페이로드에 본문 박지 않음. 트리거만.
10. 인증은 로그인 흐름. 빌드 시점 토큰 박기 X.
11. UI / 프롬프트 한국어. 코드 주석 한국어 OK.
12. 테스트 우선. 워커 / 저장소 / 데이터 접근 객체 테스트 작성 필수.
13. 로깅은 Timber (안드로이드 로깅 라이브러리). 운영 빌드에서는 로그 억제.
